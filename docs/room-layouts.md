# Схемы аудиторий на backend (CampusApp)

CampusApp **не хранит геометрию аудиторий в коде Flutter**. Координаты мест,
проходы, доска, прямоугольные блоки и розетки загружаются из MySQL и
отрисовываются одним `ServerRoomSeatMap`.

## Где хранятся данные

Таблица `campus_room_layouts` создаётся автоматически при первом обращении
к каталогу или бронированию. Начальные схемы `М-307` (54 места) и
`В-308` (176 мест) добавляются через `INSERT IGNORE`, поэтому запуск
сервера не сбрасывает ручные изменения схем.

- `room_code` — уникальный номер аудитории (например, `В-308`).
- `university`, `building`, `name`, `description` — данные о помещении.
- `enabled` — показывать ли помещение в каталоге.
- `layout_json` — геометрия и реальные идентификаторы мест.
- `updated_at` — время последнего изменения.

Брони остаются в существующей таблице `campus_room_seat_bookings`.
**Идентификатор каждого места** — `(room_code, date, slot, row, desk, seat)`.
Для В-308: `row` — внутренний ряд от задней стены, `desk` — номер места
в секторе, `seat` — сторона (1 = левая, 2 = правая). На экране показываем
номер ряда `11 - row`, чтобы счёт шёл снизу вверх.

Не перенумеровывай действующие места в JSON без миграции уже созданных броней.

## API

```http
GET /services/room-bookings/rooms
GET /services/room-bookings/rooms/%D0%92-308/layout
GET /services/room-bookings?room=%D0%92-308&date=2026-11-12&slot=1
```

Первый запрос возвращает список активных аудиторий, второй — полную схему,
третий — занятость мест **и актуальный `layout`**. Запросы на просмотр
публичные, идентификаторы занявших места студентов не раскрываются.

`POST /services/room-bookings` и `DELETE /services/room-bookings`
используют текущую подтверждённую сессию БАРС + CSRF, как раньше. Сервер
сверяет место с массивом `layout.seats` из MySQL, защищая от бронирования
несуществующих координат. Уникальные индексы в таблице броней защищают
от гонок между пользователями.

## Формат layout_json (версия 1)

```json
{
  "version": 1,
  "room": "С-401",
  "university": "НИУ «МЭИ»",
  "building": "С",
  "name": "С-401",
  "description": "Аудитория с двумя местами",
  "width": 300,
  "height": 350,
  "seats": [
    {"row":1,"desk":1,"seat":1,"x":30,"y":100,"width":27,"height":34},
    {"row":1,"desk":1,"seat":2,"x":60,"y":100,"width":27,"height":34}
  ],
  "elements": [
    {"id":"board","type":"rect","x":25,"y":20,"width":250,"height":45,"text":"Экран"},
    {"id":"outlet-1","type":"outlet","x":105,"y":105,"text":"Розетка"}
  ]
}
```

Все координаты указываются в виртуальных единицах схемы, не в физических
пикселях экрана. Flutter масштабирует карту целиком. `rotation` (радианы)
у места необязателен и позволяет создавать ряды дугами.

Типы элементов:
- `rect`: прямоугольный блок, экран, подиум, узкий проход; `x,y,width,height,text,color`.
- `line`: отрезок; `x,y,x2,y2,color`.
- `curve`: квадратичная дуга; `x,y,cx,cy,x2,y2,color`.
- `label`: надпись; `x,y,text,color`.
- `outlet`: розетка; `x,y,text`.

`color` поддерживает варианты `upper`, `lower`, `aisle`, `block`.
Каждое место должно иметь уникальную тройку `row,desk,seat`.

Для добавления новой аудитории добавь строку с корректным JSON в
`campus_room_layouts` и установи `enabled=1`. Обновлённый Flutter
получит её через каталог без пересборки. Пока редактор помещений с
правами администратора не реализован, изменение JSON делается в базе.

**Важно:** не удаляй места, на которые уже есть брони; сначала перенеси
или отменяй соответствующие бронирования. При работе с БД делай резервную
копию таблиц.

## Локальная проверка

```powershell
npm run build
npx jest room-bookings.service.spec.ts --runInBand
curl.exe "http://127.0.0.1:8000/services/room-bookings/rooms"
```

Запусти backend **до запуска Flutter**, убедись, что MySQL доступна и
пользователь БД имеет права `CREATE TABLE`, `SELECT` и `INSERT`.
