# Cloud Campus: серверное облако

Второе поколение Cloud Campus использует `/cloud` и отдельную модель
MySQL. Старые маршруты `/file` **отключены** (HTTP 410), поскольку они
позволяли читать и удалять чужие файлы без проверки владельца.

## Авторизация

Все изменения (загрузка, создание папки, сохранение, изменение прав,
удаление, генерация/отзыв ссылки) требуют существующую подтверждённую
сессию БАРС и заголовок `X-Listing-CSRF`. Клиент использует
`ListingsApi.instance.studyAuthHeaders()` и **не запрашивает второй пароль**.

Идентификатор владельца — HMAC `listingOwnerKey`, рассчитанный сервером.
Группа — только `listingGroup` из подтверждённой строки БАРС, а не из тела
запроса. Права доступа проверяются заново при **каждом** чтении файла.

### Видимость

| Режим | Кто может искать/открывать |
| --- | --- |
| `private` (новые файлы Flutter) | **Только на устройстве**: файлы не отправляются на backend и не появляются в MySQL |
| `private` (ранее загруженные на сервер) | Только владелец; **остаётся на сервере** до отдельного переноса |
| `group` | Владелец и студенты с точно такой же подтверждённой группой |
| `public` | Все; открытие разрешено без сессии |
| Ссылка | Только получатель действующего секретного токена |

Ссылка создаётся отдельно и **не меняет** режим private/group/public.
Токен генерируется случайно (32 байта), в БД сохраняется только SHA-256;
создание новой ссылки отменяет старую, отзыв обнуляет хеш.

Если пользователь сохранил чужой файл, в `campus_cloud_saved` хранится
**ярлык**, а не вторая физическая копия. Когда владелец закроет доступ или
удалит файл, чужой ярлык перестанет давать доступ.

## Личные данные только на устройстве (Flutter)

Новые файлы и папки с доступом **«Личное»** хранятся в каталоге
`campus_cloud_private` внутри application-support sandbox на Android.
Их метаданные — локальный `index.json`; отрицательные идентификаторы
позволяют отличать их от серверных. Flutter **не вызывает `/cloud/upload`**
для новых личных файлов. Операционная система не включает этот каталог
в Android Auto Backup / device-to-device transfer: для него настроены
`backup_rules.xml` и `data_extraction_rules.xml`.

При удалении данных приложения, сбросе устройства или удалении приложения
локальные файлы могут быть безвозвратно потеряны. Они не синхронизируются
между устройствами. При смене доступа отдельного личного файла на
«Моя группа» или «Всем» клиент загружает его в приватный серверный
черновик, сверяет скачанные байты и публикует результат. Локальный
исходник удаляется после проверки — двойной файл не остаётся. При
ошибке исходник сохраняется, а ID незавершённой загрузки позволяет
повторить перенос без нового дубликата.

Существующие приватные серверные файлы **не мигрируются автоматически**.
Владелец может выбрать «Настроить доступ → Личное», подтвердить скачивание
на устройство и удаление серверного оригинала. Серверную папку целиком
можно перенести аналогично: это отдельная безопасная операция, описанная
ниже. При обратном переключении локальной папки на «Моя группа» / «Всем»
приложение **переносит** папку: создаёт приватную серверную папку-черновик,
загружает файлы, сверяет скачанные байты с локальными и только после
подтверждённой проверки открывает доступ и удаляет личный оригинал.
Данные о незавершённом переносе сохраняются локально, чтобы повторная
попытка не создавалась новая папка.

Если прежняя версия создала две одноимённые копии папки у одного
владельца (одну на устройстве и одну на сервере), новый клиент показывает
**одну карточку папки** с доступом серверной копии. Обычное действие
«Настроить доступ» безопасно завершает перенос в любую сторону.
Перед удалением файлов производится сравнение байтов. При несовпадении
оба набора данных остаются доступными через общую карточку до разрешения
конфликта; одноимённые серверные папки других владельцев не объединяются.
Дополнительная кнопка «Объединить» больше не нужна.

## Перенос серверной папки обратно в «Личное»

У папки «Настроить доступ → Личное» выполняется перенос, а не только
смена поля `visibility`.

1. `GET /cloud/folders/:id/migration` (с подтверждённой БАРС-сессией и
   заголовком `X-Listing-CSRF`) возвращает полный список собственных
   файлов и сохранённых чужих материалов внутри папки.
2. Flutter скачивает каждый файл через защищённый endpoint, сверяет размер
   и одним обновлением локального индекса сохраняет полную папку в
   `campus_cloud_private`. Неполная копия не отображается.
3. Только после этого клиент вызывает
   `POST /cloud/folders/:id/migrate-to-device` с точным списком
   идентификаторов перенесённых файлов.
4. В одной транзакции MySQL backend сверяет, что состав папки не изменился,
   удаляет собственные серверные файлы, связанные с ними чужие закладки,
   закладки текущего пользователя в папке, секретные ссылки на папку и саму
   запись папки. Индивидуальные ссылки на удалённые файлы перестают работать
   автоматически. Физические файлы затем удаляются с приватного диска.

При ошибке до шага 3 сервер **ничего не удаляет**. Если после полного
локального копирования последний запрос не удался, на устройстве остаётся
копия, а серверные ссылки могут ещё действовать — интерфейс прямо об этом
предупреждает. Повторный запуск не дублирует идентичную локальную папку.

Чужие оригиналы, сохранённые в папке как закладки, **не удаляются**:
пользователь может перенести их локальные копии, но не менять доступ
другого владельца. Для папки с более чем 500 файлами необходимо сначала
разделить содержимое. При недостатке свободного места на телефоне
серверные данные остаются нетронутыми.

Для сервера важно: регулярно резервировать данные и проверять остаточные
файлы после неудачных операций удаления с диска. Отсутствие доступа по
ссылке не гарантирует немедленного уничтожения резервных копий или
физически неудалённых файлов на серверном томе.

## Импорт ссылок Яндекс Диска

Кнопка «Создать → Импорт по ссылке Яндекс Диска» принимает только **публичные
HTTPS-ссылки**. Flutter запрашивает публичный REST API Яндекс Диска напрямую
с устройства, проверяет ответ и скачивает содержимое (до 20 МиБ).
При выборе «Личное» результат записывается в sandbox; при выборе
«Моя группа» или «Всем» полученные байты загружаются в Campus Backend.
Ссылка на папку импортируется как ZIP-архив; внутри CampusApp папка
автоматически не разворачивается.

Личные ссылки, которые требуют OAuth/логина Яндекса, без отдельной
авторизации импортировать нельзя. Клиент ограничивает переходы на
неизвестные домены, не передаёт серверу произвольные URL и не загружает
файлы из локальной сети по URL.

## Схема БД

Таблицы создаются автоматически при первом запросе:

- `campus_cloud_folders`: владелец, название, доступ, группа;
- `campus_cloud_files`: владелец, файл, размер, MIME, папка, доступ, хеш ссылки;
- `campus_cloud_saved`: ссылки на сохранённые материалы и пользовательская папка.

Папки сейчас одноуровневые. Новые файлы в папке **наследуют её видимость**.
При смене доступа у папки он транзакционно обновляется для **всех её
собственных файлов**. Отдельное изменение прав файла внутри папки не
разрешено — права наследуются от папки. Перемещение собственных файлов
в папку также применяет доступ этой папки. Если в папке присутствуют
сохранённые чужие материалы, открытие папки для группы или всех
блокируется: нельзя менять доступ к файлам другого владельца.

## Папки, переименование и ссылки

Главный экран содержит отдельные разделы «Папки» и «Файлы»:
последний показывает файлы **корневого уровня**. Файлы, которые находятся в папке, показываются
после открытия этой папки. Полнотекстовый поиск по имени по-прежнему
охватывает все доступные файлы независимо от размещения, а также имена
папок. Сохранённые чужие файлы в корне личной библиотеки представлены
ярлыками и не дублируются на диске.

Владелец может переименовать файл через
`PATCH /cloud/files/:id/name` (`{"name":"Новое.pdf"}`) без изменения
содержимого и прав доступа. Для безопасности расширение файла менять
нельзя. Сохранённые чужие файлы переименовывает только оригинальный
владелец.

Ссылка на **серверную папку** создаётся через
`POST /cloud/folders/:id/link` и отзывается через
`DELETE /cloud/folders/:id/link`. Она открывает HTML-каталог
`GET /cloud/f/:token`; файлы доступны через
`GET /cloud/f/:token/files/:id`. По ссылке можно скачать только
непосредственно принадлежащие владельцу файлы внутри этой папки.
Сохранённые ярлыки на чужие файлы не публикуются.

Токены папок случайные, в MySQL сохраняются только их SHA-256-хеши
(`campus_cloud_folder_links`). Повторное создание отменяет предыдущую
ссылку. **Любой получатель действующего токена получает доступ к файлам
папки даже без входа в CampusApp** — это явно подтверждается владельцем.
Локальная личная папка на устройстве не может выдавать публичную ссылку:
для публикации содержимое необходимо загрузить в серверное облако.

## API

```http
GET    /cloud/files?mode=mine
GET    /cloud/files?mode=discover
GET    /cloud/files?mode=search&q=конспект
GET    /cloud/files?mode=mine&folderId=12
GET    /cloud/folders?mode=mine
GET    /cloud/folders?mode=discover
GET    /cloud/folders?mode=all&q=физика # поиск папок по имени с ACL

POST   /cloud/folders
PATCH  /cloud/folders/:id
DELETE /cloud/folders/:id

POST   /cloud/upload                  # multipart: file, visibility, folderId?
GET    /cloud/files/:id/download      # ACL, Content-Disposition: attachment
GET    /cloud/files/:id/preview       # ACL, только подтверждённые PNG/JPG/WebP/GIF

POST   /cloud/files/:id/save          # {"folderId": null}
DELETE /cloud/files/:id/save
PATCH  /cloud/files/:id/move          # {"folderId": 12}
PATCH  /cloud/files/:id/visibility    # {"visibility":"group"}
POST   /cloud/files/:id/link          # возвращает token и url
DELETE /cloud/files/:id/link

GET    /cloud/s/:token                # скачать по секретной ссылке без входа
DELETE /cloud/files/:id
```

Пример создания папки:

```json
{"name":"ТАУ · лабораторные","visibility":"group"}
```

`mine`: собственные файлы + сохранённые доступные файлы.
`discover`: групповые и общие файлы других авторов.
`search`: поиск по всем доступным файлами, включая собственные.
Поиск и проверка доступа выполняются на сервере, а не только во Flutter.

## Хранение байтов и эксплуатация

Метаданные — в MySQL, содержимое — на приватном диске сервера, по UUID.
Для развёртывания на нескольких серверах в будущем потребуется объектное
хранилище (S3-совместимое) либо общий том.

`CAMPUS_CLOUD_STORAGE_DIR` — абсолютный путь к **постоянному диску**
по умолчанию `./cloud-private`. Каталог не должен раздаваться веб-сервером
напрямую. Сделай резервные копии одновременно MySQL и этой директории.

`CAMPUS_PUBLIC_URL` — внешний **HTTPS origin** для ссылок, например
`https://api.campus.example` (без суффикса пути). Если не задан, Flutter
получит локальную ссылку через `CAMPUS_API_BASE_URL`, которая будет работать
только в локальной сети / при наличии ADB Reverse. Это не публичная ссылка
для студентов других устройств.

Лимиты: 20 МиБ на один файл, 5 МиБ на изображение с превью,
до 500 файлов и 500 МиБ исходных файлов на пользователя, до 100 папок.
Превью отдаётся только после проверки сигнатуры файла и прав доступа.
Файлы остальных форматов скачиваются вложением, не исполняются в браузере.

### Существующие файлы из старой таблицы cloud

Старые записи `cloud` не содержали идентификатора владельца. Нельзя
автоматически назначать их первому вошедшему студенту — это дало бы доступ
к чужим материалам. Старые данные **не удалены**, но через публичный API
больше не доступны. Их можно безопасно перенести только после подтверждения
владельца администратором или заново загрузить через новый клиент.

## Проверка

```powershell
npm run build
npx jest campus-cloud.service.spec.ts --runInBand

curl.exe http://127.0.0.1:8000/health
# Войти в БАРС через CampusApp.
# Проверить создание приватного файла, группового файла, поиск,
# сохранение у другого студента, запрет чужой приватной загрузки,
# создание ссылки, скачивание по ней и отзыв.
```

Прежде чем публиковать сервер, обязательно проверь `npm audit`
(в том числе критические зависимости), HTTPS, сохранность сессионных cookie
и работу постоянного тома.
